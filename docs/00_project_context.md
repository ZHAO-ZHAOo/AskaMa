# AI Grandma 项目背景

## 1. 产品是什么
"AI Grandma（AI 老奶奶）"是一个面向**新加坡**女性的**月经健康分诊助手**。当用户遇到月经相关问题、不确定要不要去医院时，先和它对话。它会像家里经验丰富、温柔体贴的老人一样，适当追问，然后**只给出"分级建议"**，告诉用户：
- 是不是需要立刻去急诊；
- 是不是应该尽快去看医生，去哪类机构合适；
- 还是可以在家自我照护，并告诉她怎么做、什么情况要升级就医。

## 2. 目的
- 让没事的人不要去大医院急诊凑热闹，减少不必要的拥挤和花费；
- 让该去的人及时去；
- 让只需在家观察的人知道怎么照顾自己。

## 3. 硬性原则（所有任务都必须遵守）
1. **不做任何诊断**，不说"你可能得了某某病"。只做分级和就医/自护指引。
2. **决策与表达分离**：分级结论由确定性的规则、追问流程和决策表得出，**LLM 只负责听懂用户说的话（抽取信息）和用老奶奶的口吻说话**，不能自己决定级别。
3. **安全优先**：红旗（急症）规则永远优先；信息不确定时，分级**向上升一级**；漏判代价远高于过度分诊，但过度分诊也要尽量避免（产品目标就是分流）。
4. **所有医学内容都先是草稿**（status=draft_unreviewed），必须经临床医生审核后才能视为可用。工程师不得自行编造医学阈值。
5. **一切皆数据**：规则、追问树、决策表、内容卡片、权重都放在带版本号的配置文件里，不要写死在代码或 prompt 里。
6. **隐私最小化**：月经健康数据高度敏感。只记录决策需要的字段；位置只保留区域级别；日志用匿名 session_id；不使用真实用户数据。
7. 这是学生/黑客松 MVP，不是已认证的医疗器械，界面和文档必须有免责声明位置。
8. **不设最低使用年龄门槛**：青春期用户是目标人群之一，系统不得把"只面向成年人"作为前提假设；针对青少年的表达要更简单、不吓人、不评判，怀孕相关问题的措辞必须中性、不评判，仍然不收集任何性生活史；对青少年用户应温和地鼓励其告诉一位信任的成年人，但这只是表达方式，不是使用门槛，也不能要求用户提供家长信息；默认保护隐私、数据最小化，不假设能联系到监护人。
9. **多语言**：所有用户可见文本一律使用多语言对象（`i18n_text`），英文为源文本并作为回退语言；非英文的医学文本须经母语者或临床医生审核后才能视为可靠。

## 4. 系统架构（对话流程）
```
用户输入
  → Intake：LLM 把自然语言抽取成"槽位"（结构化 JSON）
  → L1 红旗层：依据红旗规则，每一轮都评估。命中则直接输出"立即就医"出口（不是死胡同：同时给最近的 24 小时妇科急症/A&E 信息和急救电话）
  → L2 分级层：按"症状模块"的追问逻辑多轮追问，用决策表得出级别
       ├─ 级别 = SELF_CARE → L3.1 自我照护层：按"症状模块 × 级别"取内容卡片输出
       └─ 级别 = 需就医   → L4 就医推荐层：先硬过滤机构，再按权重打分排序，输出推荐
  → 人设层：用老奶奶口吻组织最终回复，并做输出校验（无诊断式措辞；说出的级别必须与 L2 结论一致）
```
L4 的排序权重**不在对话中调整**，而是在"设置页"里，用户回答几道选择题，系统自动换算成权重，存进用户档案，L4 运行时读取。

## 5. 四个级别
- `EMERGENCY_NOW`：立即就医（红旗命中）
- `SEE_DOCTOR_24_48H`：24–48 小时内就医
- `BOOK_SOON`：近期预约门诊（约 1–2 周内）
- `SELF_CARE`：居家观察与自我照护（必须附带"出现什么情况就升级就医"）

## 6. 新加坡场景要点
- 没有"三甲"概念。机构类型：`a_e`（公立医院急诊）、`urgent_og`（24 小时妇产科急症，例如 KKH Urgent O&G Centre）、`polyclinic`、`chas_gp`、`private_gp`、`private_gynae`、`soc`（公立医院专科门诊）。
- 费用高度取决于**就医路径和用户身份**：公立专科门诊的补贴通常需要从 polyclinic、公立医院 A&E 或 CHAS GP 转介才能享受；公民和 PR 的补贴不同；留学生等其他身份通常无补贴。所以"费用"特征要按用户身份和路径计算。
- 地图服务计划使用新加坡土地管理局的 OneMap API（免费，需注册，使用 token）。

## 7. 为未来优化预留的设计（MVP 不实现自我迭代，但必须埋好点）
未来会通过"错误案例归因 → 模型提出修改提案 → 医生审核 → 回归测试 → 发布"来迭代追问逻辑。因此现在必须：
- 每个配置带 version / source / reviewer / last_verified；
- 每次会话记录**所有版本号**、每轮槽位、每轮候选级别轨迹、停止追问的原因、L1 的"险情"（接近阈值但没触发的规则）、L4 的各特征得分明细；
- 每个会话生成匿名的 `outcome_link_key`，以后用于回访"医生怎么说"，居家观察的用户也要有；
- 整条流水线设计成"纯函数：(状态, 配置) → 决策"，以便以后用新版本在影子模式下重跑；
- **红旗规则永远不进入自动优化**，只能由医生手动修改。

## 9. 目标人群与年龄决策

1. AI Grandma 不设最低使用年龄门槛。初中、高中的青春期用户是目标人群之一；特别小的儿童预计不会使用（没有手机）。
2. 系统不得把"只面向成年人"作为前提假设。
3. 青春期与成年用户在临床判断上可能有差异（例如初潮后一段时间的周期规律性、各种分档的边界），这属于临床判断：**工程师不得自行设定**，红旗规则、追问逻辑、决策表需要预留按年龄段区分的空间，并由临床医生审核。
4. 针对青少年的表达要更简单、不吓人、不评判；怀孕相关问题的措辞必须中性、不评判；**仍然不收集任何性生活史**。
5. 默认保护隐私：数据最小化，不假设能联系到监护人。
6. 对青少年用户，系统应温和地鼓励其告诉一位信任的成年人，但这**只是一种表达方式，不是使用门槛**，也不能要求用户提供家长信息。
7. 未成年人给出数据使用同意（回访、研究用途）的规则，以及新加坡 PDPA 的相关规定，**尚未核实**，需要项目负责人查阅官方指引后决定。

## 11. 语言决策

1. 支持语言代码：`en`（默认，必填）、`zh`（简体中文）、`ms`（马来语）、`ta`（泰米尔语）。
2. 所有"用户可见的文本"统一使用多语言对象 `i18n_text`：`{en: string（必填，非空）, zh?: string, ms?: string, ta?: string}`。
3. **英文是源文本**，其他语言是翻译；某种语言缺少翻译时，**回退显示英文**。翻译不得改变原意。
4. 马来语和泰米尔语的医学类文本需要由母语者或临床医生审核后才能视为可靠；机器翻译只能算草稿。**至少急症出口相关的文案，在正式上线前必须有经审核的各语言版本。**
5. 用户输入也可能是四种语言之一，甚至混合使用。槽位 id 和枚举取值与语言无关；用户用什么语言说话，由 Intake 负责抽取成统一的槽位。
6. 给项目负责人看的内部文档（说明、汇报）可以继续用中文；代码标识符和配置键使用英文。
7. 日志需要记录用户语言和界面语言（后续的事件日志步骤处理）。

## 12. 工作方式
任务会按步骤逐个交给你，每一步由项目负责人检查通过后再进入下一步。你只做当前这一步，**不要提前做后面的步骤**。每次新任务开始时，请先阅读本文件。

## 13. MVP 范围与安全措施

本项目为黑客松原型，没有临床医生审核。原有的"所有医学内容必须经临床医生审核"原则（第 3 条第 4 点）作为正式上线前的要求保留，MVP 阶段的替代措施如下：

1. **每条医学内容必须引用公开权威来源**：红旗规则、决策表行、自护卡片必须附 sources（至少含 title 和 url），不得为空。
2. **来源有分歧时取更保守的**：当不同来源给出不同建议时，采用更保守（更可能建议就医）的方案。
3. **界面和文档必须显著标注**"原型，未经临床审核，不是医疗建议"。
4. **仅用于演示和合成病例**，不面向真实用户公开发布。
5. **评测只衡量与所引用指南的一致性**，不声称临床准确。
